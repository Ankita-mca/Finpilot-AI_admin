🚀 Complete Flow: From Sign In to Dashboard

Walkthrough of how a platform operator accesses the portal, authenticates, verifies role permissions, and enters the operational dashboard.

flowchart LR
    A["1. /admin Gate"] --> B["2. RoleSelection.tsx"]
    B -->|Select Platform Admin| C["3. AdminLogin.tsx"]
    C -->|Submit Credentials| D["4. POST /api/v1/auth/login/"]
    D -->|Session Created| E["5. GET /api/v1/admin/me/"]
    E -->|Verify is_staff| F["6. AppRouter.tsx (/admin/dashboard)"]
    F --> G["7. AdminLayout Shell"]
    G --> H["8. Dashboard.tsx (KPIs & Telemetry)"]
1
Gateway Access: /admin
File: frontend/src/app/AppRouter.tsx

The user requests /admin. AppRouter checks window.location.pathname.startsWith('/admin') and mounts the isolated AdminPortal. Tenant components and hooks are not initialized.

2
Operational Role Selection
File: frontend/src/admin/pages/auth/RoleSelection.tsx

Staff members select their functional role (Platform Admin, Super Admin, Support Agent, Analyst). Selecting Platform Admin navigates to /admin/login. Restricted roles display informative notification banners.

3
Staff Sign-In Submission
File: frontend/src/admin/pages/auth/AdminLogin.tsx

Input email (admin@finpilot.ai) and password. Client-side RFC 5322 regex checks valid email syntax. Submits through useAdminAuth.login() hook with interactive loading spinner.

4
Backend Session Authentication
Endpoint: POST /api/v1/auth/login/

Django backend validates credentials against the database and sets the secure, HTTP-only session cookie (sessionid) and CSRF token.

5
Platform Staff Role Verification
File: backend/platform_admin/views/auth_views.py | Endpoint: GET /api/v1/admin/me/

Backend inspects request.user:
• If is_superuser: returns role: "super_admin".
• If is_staff: returns role: "platform_admin".
• If standard customer user: returns 403 Forbidden. The frontend immediately wipes the session cookie via adminApi.logout() and shows "Access Denied".

6
Application Shell Mounting
File: frontend/src/admin/layouts/AdminLayout.tsx

Renders AdminHeader.tsx (global search, alert badge, profile menu), AdminSidebar.tsx (5 navigation categories), and AdminBreadcrumb.tsx.

7
Dashboard Telemetry Loaded
File: frontend/src/admin/pages/Dashboard.tsx

Presents KPI stat cards (Organizations: 1,248, Users: 8,642, Active Subscriptions: 986, AI Requests: 42.8K), subscription distribution ring, and real-time platform activity stream.

🛡️ Super Admin Protection Safeguards

Enforcement logic ensuring platform_admin cannot bypass into /admin/plans or /admin/staff.

// frontend/src/app/AppRouter.tsx
if (pathname === '/admin/plans' || pathname === '/admin/staff') {
  if (adminUser && adminUser.role !== 'super_admin') {
    // Intercept and redirect unauthorized staff
    navigate('/admin/dashboard')
  }
}

🔄 Dual-Mode API Mechanics

How adminApi.ts ensures zero downtime during local development.

flowchart LR
    Page["Admin Page"] --> ApiClient["adminApi.ts"]
    ApiClient --> TryLive["GET /api/v1/admin/*"]
    TryLive -->|Success| Merge["Merge Live + Demo Telemetry"]
    TryLive -->|Network Error / Offline| Fallback["Load MOCK_ORGANIZATIONS"]
    Merge --> Result["Return { items, stats, isLive: true }"]
    Fallback --> Result2["Return { items, stats, isLive: false }"]
    Result --> UI["Display 'Live API' Pill"]
    Result2 --> UI2["Display 'Demo Data Active' Pill"]
